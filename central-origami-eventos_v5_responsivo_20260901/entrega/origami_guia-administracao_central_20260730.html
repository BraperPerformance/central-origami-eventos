Guia de Administração — Central Origami INTERNO · NÃO PUBLICAR

Como publicar, versionar e manter a Central do Cliente da Origami. Este arquivo nunca entra no repositório.

1 · Visão geral

A Central Origami é um site estático: um único index.html + pasta assets/ + pasta docs/. Sem servidor e sem banco de dados. O GitHub guarda os arquivos e o Vercel publica automaticamente a cada commit (~1 minuto).

2 · Estrutura do objeto DOCS

Todos os documentos publicados vivem em um único objeto JavaScript dentro do index.html:

const DOCS = {
  plan: [
    { id:'plan-midia-fda-2026',            // nunca repetir um id
      titulo:'Plano de Mídia · Meta Ads · Festa de Fim de Ano',
      tag:'JUL/2026',
      desc:'Descrição de uma frase.',
      arquivo:'docs/origami_planejamento_midia_20260723.html' },
  ],
  report: [],   // Relatórios
  status: [],   // Status Semanais
  analise: [],  // Análises e Estudos
};

Regras críticas

  • O id deve ser único em todo o DOCS.
  • O arquivo deve bater exatamente com o nome real no disco — é case-sensitive.
  • Cada bloco { ... } termina com vírgula, inclusive o último antes do ].
  • Vírgula quebrada = portal em branco. Na dúvida, valide o trecho em jsonlint.com antes de commitar.
  • Documento mais recente sempre no topo do array — a ordem do array é a ordem na tela.

3 · Publicar um documento novo

  1. Logado no GitHub, abra a pasta docs/ → Add file → Upload files.
  2. Arraste o HTML ou PDF (nome já na taxonomia: origami_[categoria]_[descrição]_[AAAAMMDD]) → Commit changes.
  3. Abra index.html → lápis (Edit) → localize a categoria correta (plan: [, report: [, status: [ ou analise: [) → adicione o bloco no topo do array → Commit changes.
  4. Aguarde ~1 minuto → o Vercel publica sozinho. Confira com Ctrl+Shift+R.
GitHub mostrando "Sign in" no canto superior? Você está deslogado — os botões de upload não aparecem para visitante. Faça login primeiro.

4 · Substituir ou versionar um documento

  • Substituição direta (mesmo nome): antes de subir, compare o novo arquivo com o publicado — arquivo reenviado pode ser idêntico ao que já está no ar. Depois: Upload files com o mesmo nome sobrescreve.
  • Versão nova (v2): suba com data nova no nome, adicione novo bloco no topo do array e mantenha ou remova o antigo conforme o combinado com o cliente.
  • Substituir o index.html: abrir o arquivo → lápis → Ctrl+A → colar o novo conteúdo → Commit changes.

5 · Remover documento ou feature

Remoção real, não cosmética:

  1. Deletar o arquivo da pasta docs/ — enquanto existir, a URL direta continua funcionando.
  2. Remover o bloco correspondente do DOCS — a rota #/doc/id-antigo passa a redirecionar ao Início automaticamente.
  3. Testar a URL direta do arquivo e confirmar 404.

6 · Documentos com gráficos (Chart.js)

O repo carrega a biblioteca local em assets/chart.umd.js. Todo documento com gráficos deve referenciá-la com fallback CDN síncrono:

<script src="../assets/chart.umd.js"></script>
<script>
if(!window.Chart){document.write('<script src="https://cdnjs.cloudflare.com/ajax/libs/Chart.js/4.4.1/chart.umd.min.js"><\/script>')}
</script>
  • Documento recebido com src="https://cdnjs..."? Trocar o src para ../assets/chart.umd.js + fallback antes de publicar.
  • Após qualquer deploy que envolva gráficos, confirmar que assets/chart.umd.js subiu — a ausência dele deixa todos os gráficos em branco.

7 · Usuários e senhas

No index.html, objeto USERS:

const USERS = {
  cliente: { nomes: ['bruno','evandro','guilherme','barreto'], senha: '...' },
  admin:   { nomes: ['rafael','gabriel'],                      senha: '...' }
};
  • Nomes sempre em minúsculas e sem acento no array — a normalização do login cuida do resto. O login também aceita nome + sobrenome (ex.: "Bruno Silva" entra pelo registro "bruno").
  • Para adicionar usuário: incluir o primeiro nome normalizado no array do grupo correto.
  • Para trocar senha: editar o valor, commitar, avisar o grupo pelo WhatsApp.
  • O login é uma barreira organizacional, não um cofre — nunca publicar na Central nada que não possa vazar (dados individuais de leads, contratos, valores).

8 · Checagem pós-deploy

md5sum index.html assets/chart.umd.js docs/*.html docs/*.pdf

Comparar com os checksums da entrega. Divergiu = o arquivo não foi atualizado no deploy.
